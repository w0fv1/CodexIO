# Codexio

Codexio 是一个运行在 Windows 本机的消息中转工具。它适合把本机的 AI 助手、网页对话入口、飞书会话和邮件收发连接在一起，让你可以用一个稳定的本地入口处理多种消息来源。

安装完成后，Codexio 会在电脑后台运行，并在系统托盘显示图标。你可以通过双击托盘图标打开本机对话页面，也可以让其他工具通过本机地址接入它。Codexio 不依赖远程数据库，主要配置、运行状态和日志都保存在本机。

## 适合谁使用

Codexio 适合这些场景：

- 你希望在本机长期运行一个轻量消息中转入口
- 你希望把网页对话、飞书消息或邮件消息接到同一套处理流程
- 你需要一个可以随电脑启动、可以在托盘里管理的桌面工具
- 你不希望把日常对话记录默认保存到远程数据库
- 你需要在本机工作区里配合 Coding Agent 或其他自动化工具使用

如果你只是偶尔打开一个网页聊天窗口，不需要飞书、邮件或本机长期驻留能力，Codexio 可能不是必须的。但如果你希望把多个入口合成一个稳定的本地通道，它会更合适。

## 下载与安装

发布页通常会提供 Windows 安装器。下载后直接运行安装器，按提示完成安装即可。

安装时可以选择安装位置。默认情况下，卸载或升级不会删除已有配置和运行数据，这样你重新安装后仍能继续使用原来的配置。

安装完成后，你可以在开始菜单或桌面快捷方式中启动 Codexio。启动成功后，系统托盘会出现 Codexio 图标。如果你没有看到主窗口，这是正常的，Codexio 主要以托盘应用的方式运行。

## 首次启动

首次启动后，建议按下面顺序确认：

1. 查看系统托盘是否出现 Codexio 图标
2. 双击托盘图标，确认浏览器能打开本机对话页面
3. 在页面中发送一条测试消息，确认页面可以正常显示
4. 如果你要接入飞书或邮件，再进入对应配置

Codexio 首次启动会自动准备必要的本机配置。你不需要手动创建数据库，也不需要单独启动服务进程。

## 日常使用方式

### 打开对话页面

双击系统托盘中的 Codexio 图标，会使用默认浏览器打开本机对话页面。

这个页面是最直接的使用入口。你可以在这里发送消息、观察通道状态，也可以把它当作本机消息调试面板。

### 后台运行

关闭浏览器页面不会退出 Codexio。只要托盘图标还在，Codexio 仍然在后台运行。

如果你希望完全退出，请在托盘图标菜单中选择退出。直接关闭浏览器标签页只会关闭页面，不会关闭后台服务。

### 更新版本

安装新版本前，建议先退出正在运行的 Codexio。安装器默认会保留已有配置。升级后重新启动即可继续使用。

如果新版本包含配置结构调整，Codexio 会尽量沿用已有配置。升级后建议打开页面发送一条测试消息，确认通道仍然正常。

## 可连接的消息入口

Codexio 可以按需启用不同入口。你不需要一次配置所有入口，只启用当前需要的即可。

### Web 页面

Web 页面是默认入口，适合本机直接使用和基础测试。

建议先确认 Web 页面工作正常，再配置飞书或邮件。这样排查问题时可以先确定 Codexio 本身是否正常运行。

### 飞书

如果你希望在飞书里收发消息，可以配置飞书开放平台应用或飞书机器人。

飞书接入适合这些情况：

- 团队成员习惯在飞书中发起消息
- 需要把群聊或私聊里的消息交给本机处理
- 希望把处理结果回传到同一个飞书会话

首次接入飞书时，建议先在目标会话里发送一条简单测试消息，确认 Codexio 已识别当前会话。一个飞书通道通常绑定一个明确的群聊或私聊，避免多个会话混在一起导致消息归属不清。

### 飞书 Webhook

飞书 Webhook 适合只需要把结果发到飞书，不需要从飞书接收消息的场景。

例如，你只希望把某些处理结果通知到一个群里，可以使用 Webhook。它更简单，但能力也更单向。

### 邮件

邮件通道适合把指定邮箱中的来信转为输入，并通过 SMTP 发出回复。

使用邮件通道时，请注意：

- 建议使用专门邮箱，不要直接绑定私人主邮箱
- 建议只允许可信发件人触发处理
- 邮箱密码或授权码应妥善保存
- 首次配置后先用一封测试邮件验证收发链路

邮件通道只适合清晰、低频、可追踪的消息流。如果你需要高频实时对话，建议优先使用 Web 页面或飞书。

## 配置建议

Codexio 的配置保存在本机。正常使用时，你通常不需要频繁修改配置文件。

建议遵循这些原则：

- 先启用最少入口，确认正常后再逐步增加
- 一个入口只绑定一个明确用途
- 不要把测试通道和正式通道混在一起
- 修改配置前先退出 Codexio
- 修改后重新启动，并发送测试消息确认结果

如果你不确定某个配置项的含义，不要直接复制来源不明的配置。优先从最小可用配置开始。

## 数据与隐私

Codexio 默认不把对话记录保存到远程数据库。它主要在本机处理消息转发和运行状态。

仍然需要注意：

- 你发送到飞书、邮件或其他外部通道的内容，会进入对应平台
- 本机配置可能包含令牌、邮箱授权码或 Webhook 地址
- 不要把配置文件发给无关人员
- 共享电脑上使用时，建议确认系统账号和磁盘权限

如果你要处理敏感信息，建议先确认所有外部通道的权限、日志和保留策略。

## 常见操作

### 打开页面后没有消息

先确认托盘图标仍在。然后刷新浏览器页面，再发送一条新的测试消息。

如果页面只显示已连接状态但没有历史消息，这是正常的。Codexio 不把历史对话当作长期消息库，新页面通常只显示新发生的通道消息。

### 飞书没有响应

按顺序检查：

1. Codexio 是否正在运行
2. 飞书应用或机器人是否启用
3. 当前会话是否已经完成绑定
4. 飞书侧权限是否允许接收和发送消息
5. 是否把消息发到了正确的群聊或私聊

如果刚修改过飞书配置，建议退出并重新启动 Codexio。

### 邮件没有被处理

按顺序检查：

1. 邮箱地址和授权码是否正确
2. 发件人是否在允许范围内
3. 邮件是否进入了配置的收件箱
4. 邮件是否已经被标记为已读
5. 邮箱服务商是否限制了 IMAP 或 SMTP

很多邮箱需要单独开启 IMAP/SMTP，并使用授权码而不是登录密码。

### 托盘图标还在，但页面打不开

可以先退出 Codexio，再重新启动。

如果仍然打不开，可能是本机端口被其他程序占用，或者安全软件拦截了本机服务。此时可以查看日志，确认启动是否成功。

### 升级后配置不符合预期

安装器默认保留配置。如果你希望彻底重新开始，可以先备份需要保留的信息，再在卸载时选择清理用户数据，或手动清理 Codexio 的本机数据目录。

不建议在不备份的情况下直接删除配置，尤其是已经配置过飞书、邮件或 Webhook 的环境。

## 使用建议

- 把 Codexio 当作本机消息入口，而不是长期知识库
- 重要结果应保存到你的正式工作系统中
- 飞书、邮件等外部通道先小范围试运行
- 每次升级后做一次 Web 页面测试和关键通道测试
- 不使用的通道及时关闭，减少误触发
